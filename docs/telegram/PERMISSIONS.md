# Adapter × permission matrix

This document records what each CLI adapter is started with at every permission level (`strict`, `standard`, `full`) and what capabilities (file editing, shell execution, network access) are permitted.

Permission levels are configured under `adapter.permissions` in `config.yaml` (default: `full`).

Per the Round 5 scope cut, this matrix documents the **Claude**, **Codex**, and **Antigravity** adapters. Other adapters follow in subsequent rounds.

## Notes and Scope

- **Defaults**: Default permission level across all adapters remains `full` (`DEFAULT_PERMISSIONS = "full"` in `swarmly.telegram.config`). No defaults or adapter codes are modified in this round.
- **Custom command template override**: Setting an explicit `adapter.command` in `config.yaml` bypasses template generation and overrides all level flags.
- **Antigravity permission behavior**: `adapter.permissions` has no entry in `PERMISSION_FLAGS` for `antigravity` or `antigravity_thread`. Sandboxing (`--sandbox`) and approval bypass (`--dangerously-skip-permissions`) are controlled solely via an explicit `adapter.command` (using `sandboxed(settings)` and `skips_approvals(settings)`).
- **Hermes and other adapters**: Hermes and remaining adapters are deferred to later rounds per coordinator/admin directive for #140.
